An activity type register contains descriptions of activity types.

Activity types themselves will have a reference to descriptive model that defines how instances of the activity execution will be realised as a prov:Activity - i.e. the ItemClass will be a profile of prov:Activity and execution records will be instances of prov:Activity.

## Documentation

- [Activity type registers: layers, new projects and promotion](docs/activity-type-registers.md) ([PDF](docs/activity-type-registers.pdf)): how the RIM, this register (generic activity types) and project registers such as [ospd-activity-types](https://github.com/ogcincubator/ospd-activity-types) fit together, how a new project declares its own types, and how a specific type is promoted to a generic one.
